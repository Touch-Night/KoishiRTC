## QQ Linux 真实验收顺序

1. 安装与身份：Host 找到正确库指纹；控制桥报告真实 QQ 号；媒体桥配置同号；管理员页面显示实际能力。
2. 私聊来电：从测试账号呼叫，页面显示 ringing 且目标正确；明确接听后等待平台 connected。
3. 双向声音：测试者讲话，检查电平和连续 PCM；点击“播放测试音”，由测试者确认听见；两条音频线路不产生自回声。
4. 中断：静音后不继续播放旧队列；取消静音不会恢复被打断的回复；清空操作保留已播放/已发送进度。
5. 结束：分别测试对方挂断、本端挂断、拒接和无人接听；最终状态靠平台回调或已审计的本端空闲查询，不能只看 HTTP 200。独立记录远端是否确认结束。
6. 主动拨号：由测试者明确指定自己的账号，再验证发起、对方接听和本端取消。
7. 群语音：测试者先建立语音房间；在最近活跃群列表选择加入；确认双向音频与成员列表；退出后保持群内其他成员不受影响。
8. 故障：媒体桥断线、音频设备移除、控制桥重启；停止采集且不回落默认设备，不重放未知结果的拨号。
9. 恢复：停止实验进程及专用音频服务，按保存的原命令启动原 QQ，确认 Koishi 适配器恢复。

群语音混音不包含可靠发言者 ID。成员进入/退出事件也不能作为声纹标签。

## QQ Linux 视频验收

1. 当前通话必须由原生回调确认 `connected`，视频能力须匹配已审核的 Linux QQ 画像。
2. 由测试者打开自己的摄像头或共享内容；选择该成员的真实 UID，订阅对应渠道。确认首帧事件与图像捕获均属于该通话/成员。
3. 验证横屏、竖屏、比例变化和成员关闭画面，不以占位色块或视频尺寸事件代替首帧。
4. 分别验证直接发出屏幕邀请（`dialScreen`）和已接通语音中通过 `sendVideo` 开启屏幕共享。后者在已审计 QQ 构建上走官方通话转换，须检查同一逻辑 callId、新房间双方连接、远端真实画面与音频恢复；不能把旧通话的 ACK 当作转换成功。验证视频/屏幕邀请的预选来源在接通后自动开始，释放控制或取消时不迟到重新开启。发送端明确枚举并选择来源；设备/窗口发送与插件提供 JPEG 帧分别验收。`external-frames` 只渲染消费插件提供的内容，不捕获桌面；虚拟摄像头路线未实测时保持待验收。
5. 消费插件连续提交帧时检查序号、丢旧帧回执、PCM 连续性；由远端测试者确认实际看到内容。仅收到本端 ACK / `rendered` 不算远端验收成功。
6. 停止观看、停止发送、释放控制权、关闭控制台、token 过期、通话结束和成员退出后，验证不继续提供旧画面、不发送积压帧；无需为了释放媒体而挂断仍在使用的通话。

Linux 原生视频已完成画像静态核对，ARM64 的真实视频通话正在分项验收；已确认结果见下方记录。x64 的静态支持、Windows/macOS 音频支持以及离线测试通过，都不能写成对应平台视频实机通过。

## Windows / macOS

先按系统文档执行只读诊断和原生设备选择，再重复上述真实通话检查。Windows 10 不假定存在系统进程级 loopback API，使用明确的两条虚拟线路。macOS 必须处理签名、麦克风权限和独立账号容器，不能仅凭静态检查通过就标记验收。

需要人工确认的结果在测试记录中标为 pending，不能用接口成功或伪造音频事件替代。

## 2026-10-06 主动关闭状态同步补充

此项是静态核验与离线回归记录，不覆盖上方真实通话日志。Close 10 的 ARM64 实现将任务投递到 thread 101 后返回 0；`OnCloseSession` 的 reason 0 分支不转发 20022，20013 则是其他终端状态通知。因此 ACK、20013 和普通 Kernel S2C 元数据都不能单独作为本端关闭完成的依据。地址、固定库指纹和返回布局见[私聊关闭协议研究](qq-private-screen-research.md#主动结束的本端空闲确认)。

新增关闭确认仅对独立核验过的 Linux ARM64 / x64 画像启用命令 14。Scene 1 Close 10、Scene 2 Quit 8、Scene 3 Quit 8 的成功 ACK 后最多进行 6 次只读查询；只有相关 `[0, "", "0"]` 使本端进入 `ended`，并保留 `remoteEndedConfirmed=false`。非零房间、空字符串、错误返回、超时和传输失败都保留待结束状态；预算用完后显示未确认原因，允许用户明确重试清理。群成员离房确认仍保留。

本轮 `node --test bridge/qq/tests/controller.test.mjs bridge/qq/tests/host.test.mjs` 为 **62/62 通过**，全部使用离线 fake，未启动 QQ、访问设备或操作正在进行的通话。覆盖三个 scene、未审计画像拒绝、无关请求、未知结束、有限轮询、旧关闭请求、controller 停止、Host generation 变化，以及旧查询超时后的迟到 `"0"` / HTTP 拒绝不会污染新查询；还覆盖原生结果先于 HTTP 提交回执。代码复核确认非零房间路径只会重查或保留 `ending`，不进入结束分支。
